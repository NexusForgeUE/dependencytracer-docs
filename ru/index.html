Установка

Dependency Tracer 1.1.0 поддерживает Unreal Engine 5.5, 5.6, 5.7 и 5.8 на Windows 64-bit. Выберите пакет для своей младшей версии движка.

Установка через Fab

  1. Найдите Dependency Tracer в своей Fab Library в Epic Games Launcher и установите его для соответствующего движка.
  2. Откройте проект. В Edit > Plugins найдите Dependency Tracer и при необходимости включите его.
  3. Перезапустите редактор и откройте Tools > Dependency Tracer.

Ручная установка из исходников

  1. Закройте Unreal Editor. Оставьте одну установку плагина: старая копия в проекте может использоваться вместо установки в движке.
  2. Поместите папку DependencyTracer из архива в каталог Plugins проекта. Дескриптор должен находиться по указанному ниже пути.
  3. Пакету исходников нужны C++ инструменты сборки, поддерживаемые вашей точной версией движка. Соберите editor target проекта либо заранее соберите плагин инструментом Unreal BuildPlugin.
  4. Откройте проект, при необходимости включите Dependency Tracer, перезапустите редактор и откройте Tools > Dependency Tracer.

Первое сканирование

Начните со знакомой части проекта. Сохраните изменённые ассеты, чтобы размеры пакетов соответствовали их последнему сохранённому состоянию. Плагин сначала открывает Dependency Tree; после сканирования переключитесь на Overview. Названия кнопок в руководстве оставлены на английском, как в интерфейсе плагина.

  1. Выберите контент для анализа. Откройте Project Settings > Plugins > Dependency Tracer. Оставьте Analysis Roots равным /Game для всего проекта или выберите меньшую папку, например /Game/Characters.
  2. Просканируйте проект. Откройте Tools > Dependency Tracer и нажмите Scan project. Дождитесь окончания. Дополнительный аудит Blueprint запускается через Scan + audit или Run Blueprint Audit.
  3. Начните с Overview. Проверьте количество ассетов, размеры контента, типы и крупнейшие корневые зависимости.
  4. Проследите тяжёлый ассет. В Dependency Tree выберите его через Find asset либо выделите в Content Browser и нажмите Use selected. Выбирайте карточки, чтобы изучить размеры и связи.
  5. Проверьте кандидатов. Откройте Unused Assets. Используйте Browse и Open, чтобы понять назначение ассета перед изменениями.
  6. Зафиксируйте результат. Для подготовки обновления запустите Migration Audit, затем экспортируйте CSV или JSON для проверки.

После изменений ассетов или настроек запустите новое сканирование. Если карта сообщает, что показывает прежний снимок графа, нажмите Reload map.

Область анализа и корни

Область анализа — набор проверяемых ассетов. Корень — исходный ассет, который считается используемым; достижимые от него по hard- или soft-связям ассеты сохраняются при анализе неиспользуемого контента.

  • Analysis Roots: пути контента, включённые в анализ. По умолчанию /Game.
  • Excluded Folders: исключённые пути, даже если они находятся внутри включённой папки.
  • Additional Root Folders: папки с контентом, который нужно считать используемым, в том числе загружаемым динамически.
  • Include Plugin Content / Include Engine Content: расширение области анализа. Оба параметра по умолчанию выключены.

Используйте пути пакетов Unreal, например /Game/Characters, а не пути папок Windows. Корни также определяются поддерживаемой конфигурацией карт, упаковки и управления ассетами. Все карты в области считаются корнями. Если в настройках упаковки включён Cook All, все ассеты области считаются используемыми и список кандидатов может быть пуст.

Additional Root Folders добавляет корни для сохранения контента, но не расширяет область сканирования. Если нужно полноценно анализировать такую папку, включите её также в Analysis Roots.

Явно укажите динамический контент. Пути, собираемые в C++, строки из файлов и внешние системы загрузки могут не появиться в ссылках Asset Registry. Добавьте соответствующие папки в Additional Root Folders и проверьте пути загрузки игры.

Сканер перепроверяет изолированных кандидатов по всему Asset Registry, включая ссылки извне выбранной области. Это повышает уверенность, но не позволяет обнаружить каждую динамическую ссылку во время игры.

Обзор проекта

Overview показывает итог последнего завершённого сканирования. Здесь удобно выбрать тип контента или корень для дальнейшего исследования.

  • Scanned content: известные размеры пакетов на диске в заданной области, количество ассетов и пропущенных элементов.
  • Size by asset type: крупнейшие типы и их доля в известных размерах контента.
  • Largest root footprints: корни с тяжёлыми цепочками hard-зависимостей.
  • Сводка неиспользуемого контента: количество кандидатов, ручных проверок и потенциальный освобождаемый объём. Потенциальный объём суммирует известные размеры итоговых кандидатов Safe to delete.

Неизвестные размеры не входят в суммы известных размеров. Числа относятся к области анализа и не обозначают размер всей папки проекта.

Размеры и зависимости

Top roots помогает исследовать корни с большим суммарным размером hard-зависимостей. By type показывает типы ассетов с наибольшим вкладом в известные размеры пакетов.

Прямой размер и размер с зависимостями
ПоказательЗначение
Direct sizeИзвестный сохранённый размер собственного пакета ассета.
Inclusive hard sizeПакет корня и достижимые hard-зависимости; каждый пакет учитывается один раз внутри этого набора.
Общие зависимостиОдин пакет может входить в наборы нескольких корней. При сложении размеров корней он будет посчитан несколько раз.
Неизвестный или неполный размерИзвестное значение может быть нижней границей. Знак ≥ обозначает неполный расчёт.

Размер сначала берётся из Asset Registry; при отсутствии значения используется размер сохранённого файла пакета. Это оценка веса контента. Cooking, сжатие, целевая платформа и настройки упаковки могут изменить итоговый размер игры. Для точного размера поставки измерьте собранную cooked-версию.

Карта зависимостей

  1. Выберите корень через Find asset, выделите ассет в Content Browser и нажмите Use selected либо введите путь пакета и нажмите Load map.
  2. Dependencies показывает используемые им ассеты, а Referencers — ассеты, которые ссылаются на него.
  3. Выберите фильтр Hard + Soft, Hard only или Soft only.
  4. Выберите карточку. Справа изучите прямой размер и размер с зависимостями, счётчики ссылок, вес видимых зависимостей и записанные замечания аудита.
  5. Продолжите исследование через Open Blueprint или Open asset, Show in browser, Copy path и Focus asset.

Как читать линии

Сплошные золотые линии — hard-ссылки. Пунктирные серо-голубые линии — soft-ссылки. Стрелки сохраняют фактическое направление ссылки и в Dependencies, и в Referencers. Точки обозначают общие развилки; разрыв пунктира на пересечении не является соединением.

Soft-ссылка может убрать прямую hard-зависимость, но загружаемый через неё ассет всё равно может требоваться игре. Показанный суммарный размер и диаграмма веса относятся к hard-зависимостям.

Статус сообщает об обрезанных или пропущенных связях; сфокусируйтесь на другом ассете, чтобы изучить их дальше. Настройки глубины и дочерних узлов относятся к Tree view, а не к этим ограничениям карты. Диаграмма инспектора описывает видимые hard-зависимости, а не все ассеты проекта.

Аудит Blueprint

Migration Readiness Report входит в Dependency Tracer 1.1.0 и помогает подготовить структуру Blueprint перед миграцией движка.

  1. Настройте область анализа и исключения для слоя Blueprint, который хотите проверить.
  2. Откройте Migration Audit. Нажмите Run Blueprint Audit либо Scan + audit в верхней панели.
  3. Проверьте количество найденных и изученных Blueprint и ошибки инспекции. Сначала рассмотрите Blockers, затем Warnings и Info.
  4. Выберите замечание: посмотрите доказательства, стабильный Rule ID, структуру Blueprint и рекомендуемое действие. Откройте его через Open Blueprint или Show in Content Browser.
  5. Экспортируйте результат, внесите подходящие проекту изменения, вручную скомпилируйте и протестируйте Blueprint, затем повторите аудит.

Сначала проверьте покрытие

  • Аудит не запускался: обычное сканирование не включало дополнительную проверку Blueprint.
  • Blueprint не найдены: проверьте область анализа и исключения, если результат неожиданный.
  • Ошибки инспекции: часть ассетов не удалось прочитать; покрытие неполное.
  • Завершено: запланированная инспекция и анализ закончены. Это не подтверждение совместимости с целевым движком.

Инспекция Blueprint запускается отдельно и загружает ассеты области в память. Она читает текущее состояние компиляции загруженного Blueprint, но не вызывает компиляцию, не меняет родителя, не реконструирует, не удаляет и явно не сохраняет ассеты. Загрузка движком может влиять на состояние в памяти; аудит не сохраняет его незаметно и не очищает уже установленный dirty-флаг.

Проверьте миграцию в копии проекта. Отчёт находит текущие структурные проблемы и поводы для проверки. Изменения API и сериализации движка, поведение C++ и динамические ссылки нужно проверять в реальной целевой версии.

Справочник правил

Blockers обозначают текущую проблему или пробел в подготовительном аудите. Warnings включают структурные эвристики, которые стоит изучить. Info указывает провайдеров для проверки в целевом движке.

Правила аудита в версии 1.1.0

BP_MISSING_PARENTBlockerУ Blueprint, которому нужен родитель, он отсутствует в загруженном состоянии.
BP_COMPILE_ERRORBlockerТекущее загруженное состояние сообщает об ошибке компиляции.

Подсчёт связанности не учитывает ссылки на самого себя. Связанность и циклы проверяются по прямым hard-связям между Blueprint в области аудита; soft-ссылки, Blueprint вне области и пути через другие типы ассетов в эти проверки не входят. Нативные классы не считаются предками Blueprint. Проверка провайдеров также изучает нативных родителей и вызовы.

Порог — повод для проверки, а не предел совместимости. Измените значения в настройках под архитектуру проекта; экспорт фиксирует использованные значения.

Экспорт CSV и JSON

  1. Дождитесь завершения сканирования. Если нужны замечания миграции, предварительно запустите дополнительный аудит Blueprint.
  2. Выберите Export в верхней панели либо Export CSV / Export JSON в Migration Audit.
  3. Посмотрите путь созданного файла в интерфейсе. Кнопки экспорта Migration Audit также копируют его в буфер обмена.
  4. Найдите файлы в <Project>/Saved/DependencyTracer/ или в каталоге Report Export Dir.

Оба формата экспортируют отчёт сканирования с доступными данными аудита. Экспорт из аудита не ограничивается строками, видимыми под текущим поиском или фильтром важности.

  • CSV: изучите разделы отчёта в табличном редакторе или отправьте их на проверку.
  • JSON: сохраните структурированный снимок для сравнения или собственных инструментов.

Данные миграции включают покрытие, замечания, метрики каждого Blueprint и использованные пороги. CSV содержит несколько разделов; JSON использует схему версии 1.0. Полный граф зависимостей не экспортируется. Сравнивайте отчёты с одинаковой областью и настройками: изменение области может объяснять изменение итогов и замечаний.

Последующее обычное сканирование заменяет результат аудита отчётом без включённого аудита. При отмене или ошибке сохраняется предыдущий завершённый отчёт. После повторного открытия редактора выполните новое сканирование.

Решение проблем

Dependency Tracer отсутствует в Tools

Включите плагин в Edit > Plugins и перезапустите редактор. Проверьте расположение дескриптора внутри папки плагина и соответствие пакета версии движка. Для ручной установки исходников нужны совместимые C++ инструменты и успешная сборка editor target.

Сканирование пустое или не видит папку

Проверьте Analysis Roots и Excluded Folders. Используйте путь пакета, например /Game/Characters. При необходимости включите контент плагинов и запустите новое сканирование.

Размер неизвестен или меньше ожидаемого

Сохраните ассет и повторите сканирование. Размеры берутся из известных размеров пакетов на диске; неизвестные и несохранённые размеры могут не учитываться, а неполное исследование даёт нижнюю границу. Cooked-вывод может отличаться от сохранённых пакетов.

Кандидат на удаление на самом деле загружается игрой

Проверьте динамические пути и внешние системы загрузки. Добавьте папки в Additional Root Folders и повторите анализ. Поиск ссылок не может вывести все загрузки по строковым путям во время игры.

Карта зависимостей показывает старый результат

Дождитесь окончания нового сканирования и нажмите Reload map. Проверьте корень и hard/soft фильтр. Лимиты отображения могут скрыть часть связей; сфокусируйтесь на другом узле для исследования.

Migration Audit сообщает, что аудит не запускался

Обычный Scan project не изучает графы Blueprint. В Migration Audit нажмите Run Blueprint Audit или Scan + audit.

Не удалось изучить Blueprint

Откройте ассет вручную. Проверьте отсутствующих родителей, провайдеров и проблемы пакета. Устраните их и повторите аудит; до этого покрытие остаётся частичным.

Замечания не отображаются

Очистите поиск, включите все фильтры важности и проверьте количество изученных Blueprint и область анализа. Завершённый аудит без замечаний означает, что текущие правила ничего не нашли; это не сертификат будущей миграции.

Отчёт не экспортируется

Дождитесь окончания анализа. Проверьте каталог вывода и права записи. Посмотрите сообщения Dependency Tracer в Window > Developer Tools > Output Log.

Unreal сообщает об отсутствующих или несовместимых модулях

Выберите архив для точной младшей версии движка и проверьте дублирующиеся установки плагина. Исходники нужно собрать совместимыми C++ инструментами. Не помещайте в установку DLL от другой версии движка.

Частые вопросы

Плагин удаляет или переписывает мои ассеты?

Unused Assets показывает кандидатов и действия для перехода к ассету. Инспекция Blueprint загружает ассеты, но явно не компилирует и не сохраняет их. Изменения и очистка выполняются отдельно после вашей проверки.

Потенциальный объём означает гарантированно освобождённое место?

Это известный размер пакетов кандидатов для проверки. Перед удалением подтвердите, что они не используются. Зависимости, cooking и сжатие влияют на состав и размер конечной игры.

Можно сложить размеры крупнейших корней?

Несколько корней могут использовать одни зависимости. Сложение их суммарных размеров повторно учитывает общие пакеты. Для другого представления используйте суммы по типам или измеренную сборку.

Чистый аудит гарантирует успешную миграцию?

Нет. Отчёт проверяет текущую структуру и загруженное состояние Blueprint. Проверьте копию проекта в целевом движке, включая C++, провайдеров, контент и поведение.

Migration Readiness Report входит в плагин?

Да. Отчёт входит в Dependency Tracer 1.1.0 вместе с инструментами зависимостей и размеров.

Готовой игре нужен Dependency Tracer?

Модуль плагина предназначен только для редактора. Интерфейс исследования не работает внутри упакованной игры.

Для анализа нужен онлайн-сервис?

Анализ выполняется локально в Unreal Editor. Отчёты CSV и JSON сохраняются в выбранный локальный каталог.

Демонстрационный проект и снимки являются частью моего анализа?

Снимки показывают специально созданный демопроект. Ваше сканирование использует настроенные ассеты вашего проекта. Примерные числа и замечания из руководства не являются заранее подставленными результатами плагина.

Версия и поддержка

Руководство описывает Dependency Tracer 1.1.0 для Unreal Engine 5.5, 5.6, 5.7 и 5.8 на Windows 64-bit.

Что входит в 1.1.0

Интерфейс Project Atlas с карточками зависимостей и инспектором, hard/soft маршруты, исследование неиспользуемого контента, размеры по корням и типам, экспорт CSV/JSON и Migration Readiness Report для Blueprint.

Совместимость движка проверялась на UE 5.5.4, 5.6.1, 5.7.4 и 5.8.0 под Win64. Запуск на Mac и Linux не проверялся в среде тестирования этого релиза.
