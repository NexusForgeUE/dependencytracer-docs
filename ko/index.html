설치

Dependency Tracer 1.1.0은 Windows 64비트의 Unreal Engine 5.5, 5.6, 5.7, 5.8을 지원합니다. 엔진의 마이너 버전에 맞는 패키지를 설치하세요.

Fab에서 설치

  1. Epic Games Launcher의 Fab 라이브러리에서 Dependency Tracer를 찾아 해당 엔진 버전에 설치하세요.
  2. 프로젝트를 여세요. Edit > Plugins에서 Dependency Tracer를 검색하고 필요한 경우 활성화하세요.
  3. 에디터를 다시 시작한 뒤 Tools > Dependency Tracer를 여세요.

소스에서 수동 설치

  1. Unreal Editor를 닫으세요. 플러그인은 한 곳에만 설치하세요. 프로젝트에 남아 있는 이전 복사본이 엔진에 설치한 버전보다 우선 적용될 수 있습니다.
  2. 압축 파일의 DependencyTracer 폴더를 프로젝트의 Plugins 디렉터리에 넣으세요. 플러그인 설명 파일은 아래에 표시된 경로에 있어야 합니다.
  3. 소스 패키지에는 사용 중인 정확한 엔진 버전에서 지원하는 C++ 빌드 도구가 필요합니다. 프로젝트의 에디터 타깃을 빌드하거나, 설치 전에 Unreal의 BuildPlugin 도구로 플러그인을 빌드하세요.
  4. 프로젝트를 열고 필요한 경우 Dependency Tracer를 활성화한 뒤 다시 시작하고 Tools > Dependency Tracer를 여세요.

소스 제출용 압축 파일과 처리된 Fab 설치 패키지는 배포 과정이 다릅니다. 소스 압축 파일을 수동으로 설치하면 컴파일을 요청할 수 있습니다. 특정 엔진 마이너 버전용으로 빌드한 DLL은 다른 마이너 버전에서 재사용할 수 없습니다.

첫 스캔

프로젝트에서 익숙한 부분부터 시작하세요. 수정한 에셋을 먼저 저장해 디스크의 패키지 크기에 최신 저장 상태가 반영되도록 하세요. 작업 화면은 처음에 Dependency Tree를 엽니다. 스캔 후 Overview로 전환하세요. 이 가이드에서는 플러그인 인터페이스와 대조할 수 있도록 버튼 이름을 영어로 유지합니다.

  1. 스캔할 콘텐츠를 선택하세요. Project Settings > Plugins > Dependency Tracer를 여세요. 프로젝트 전체를 분석하려면 Analysis Roots를 /Game으로 유지하거나, /Game/Characters처럼 더 작은 폴더를 선택하세요.
  2. 프로젝트를 스캔하세요. Tools > Dependency Tracer를 열고 Scan project를 클릭한 뒤 스캔이 끝날 때까지 기다리세요. 선택 기능인 블루프린트 감사는 Scan + audit 또는 Run Blueprint Audit 버튼을 선택하면 실행됩니다.
  3. Overview부터 확인하세요. 스캔한 에셋 수, 콘텐츠 크기, 에셋 유형, 크기가 가장 큰 루트를 확인하세요.
  4. 큰 에셋을 추적하세요. Dependency Tree를 열고 Find asset으로 선택하거나 콘텐츠 브라우저에서 에셋을 선택한 뒤 Use selected를 클릭하세요. 카드를 선택해 크기와 참조를 확인하세요.
  5. 후보를 검토하세요. Unused Assets를 여세요. 에셋을 변경하기 전에 Browse와 Open으로 용도를 확인하세요.
  6. 결과를 기록하세요. 업그레이드를 준비할 때 Migration Audit 탭을 실행하고 검토용 CSV 또는 JSON을 내보내세요.

에셋이나 설정을 변경한 경우 새 스캔을 실행하세요. 맵의 스냅샷이 이전 스캔에서 생성되었다고 표시되면 Reload map 버튼을 사용하세요.

스캔 범위와 루트

범위는 검사할 에셋의 집합입니다. 루트는 사용 중인 것으로 취급하는 시작 에셋입니다. 미사용 콘텐츠 분석은 루트의 하드 참조 또는 소프트 참조를 통해 도달할 수 있는 에셋을 보존합니다.

  • Analysis Roots: 분석에 포함할 콘텐츠 경로입니다. 기본값은 /Game입니다.
  • Excluded Folders: 분석에서 제외할 경로입니다. 포함된 폴더 안에 있어도 제외됩니다.
  • Additional Root Folders: 내부 에셋을 사용 중인 것으로 취급할 폴더입니다. 게임에서 동적으로 로드하는 콘텐츠도 포함됩니다.
  • Include Plugin Content / Include Engine Content: 필요에 따라 범위를 확장하는 설정입니다. 두 항목 모두 기본적으로 꺼져 있습니다.

/Game/Characters 같은 Unreal 패키지 경로를 사용하세요. Windows 폴더 경로는 사용할 수 없습니다. 지원되는 맵, 패키징 및 에셋 관리 설정에서도 루트가 지정됩니다. 범위 안의 모든 맵은 루트로 취급됩니다. 패키징 설정에서 Cook All이 활성화되어 있으면 범위 안의 모든 에셋을 사용 중으로 취급하므로 미사용 목록이 비어 있을 수 있습니다.

Additional Root Folders는 보존할 루트를 추가하지만 스캔 범위를 넓히지는 않습니다. 폴더의 콘텐츠를 전체 분석하려면 해당 폴더를 Analysis Roots에도 포함하세요.

동적 콘텐츠를 명시하세요. C++에서 조합한 경로, 파일에서 읽은 문자열, 외부 런타임 시스템은 에셋 레지스트리 참조에 나타나지 않을 수 있습니다. 적절한 폴더를 Additional Root Folders에 추가하고 게임의 로딩 경로를 확인하세요.

스캐너는 선택한 범위 밖의 참조를 포함해 전체 에셋 레지스트리에서 고립된 후보를 다시 확인합니다. 결과의 신뢰도를 높여 주지만 모든 동적 런타임 참조를 발견할 수는 없습니다.

프로젝트 개요

Overview는 최근에 완료된 스캔을 요약합니다. 여기에서 주의 깊게 살펴볼 에셋 종류나 루트를 선택하세요.

  • Scanned content: 설정된 범위에서 확인된 디스크상의 패키지 크기와 에셋 수, 건너뛴 수입니다.
  • Size by asset type: 스캔에서 확인된 전체 바이트 중 차지하는 비중에 따라 가장 큰 에셋 유형을 보여 줍니다.
  • Largest root footprints: 하드 참조로 도달하는 전체 종속성의 크기가 큰 루트입니다.
  • Unused summary: 후보 수, 수동 검토 대상 수, 회수 가능 크기입니다. 회수 가능 크기는 최종적으로 Safe to delete로 분류된 후보의 확인된 크기만 합산합니다.

크기를 알 수 없는 패키지는 확인된 크기 합계에서 제외됩니다. 이 수치는 스캔 범위를 나타내며 전체 프로젝트 폴더의 크기는 아닙니다.

미사용 에셋

감지된 사용 중인 루트에서 도달할 수 없는 에셋을 검토하세요. 각 항목에는 에셋 유형, 확인된 직접 크기, 신뢰도, 해당 에셋을 참조하는 에셋 수가 표시됩니다.

빌드 크기

Top roots로 하드 참조 종속성을 포함한 크기가 큰 루트를 분석하세요. By type으로 확인된 패키지 바이트를 가장 많이 차지하는 에셋 유형을 확인하세요.

값의미
직접 크기해당 에셋 자체의 저장된 패키지에서 확인된 크기입니다.
하드 종속성을 포함한 크기루트 자체의 패키지와 하드 참조로 도달할 수 있는 종속성의 합계입니다. 해당 루트의 크기를 계산할 때 각 패키지는 한 번만 집계됩니다.

크기는 먼저 에셋 레지스트리의 패키지 크기에서 조회하며, 조회할 수 없으면 저장된 패키지 파일의 파일 시스템 크기를 사용합니다. 이 크기는 빌드 용량의 추정 지표입니다. 쿠킹, 압축, 대상 플랫폼, 패키징 설정에 따라 실제 배포 크기는 달라질 수 있습니다. 실제 배포 크기가 필요하면 쿠킹된 빌드를 측정하세요.

종속성 트리

  1. Find asset으로 루트를 선택하거나 콘텐츠 브라우저에서 에셋을 선택한 뒤 Use selected를 클릭하세요. 패키지 경로를 입력하고 Load map 버튼을 클릭할 수도 있습니다.
  2. Dependencies를 선택하면 해당 에셋이 참조하는 에셋을 추적하고, Referencers를 선택하면 해당 에셋을 참조하는 다른 에셋을 분석할 수 있습니다.
  3. Hard + Soft, Hard only, Soft only로 맵을 필터링하세요.
  4. 카드를 선택하세요. 오른쪽 검사기에서 직접 크기, 종속성을 포함한 크기, 참조 수, 표시된 종속성의 크기 비중, 기록된 마이그레이션 감사 결과를 확인하세요.
  5. Open Blueprint 또는 Open asset, Show in browser, Copy path, Focus asset으로 분석을 이어가세요.

연결선 이해

황동색 실선은 하드 참조이고 청회색 파선은 소프트 참조입니다. 종속성과 참조자 보기 모두에서 화살표는 실제 참조 방향을 따릅니다. 점은 공유 분기점을 나타냅니다. 교차 지점에서 파선이 끊어진 부분은 연결 지점이 아닙니다.

소프트 참조는 직접 하드 종속성을 피할 수 있지만, 소프트 참조로 로드하는 에셋도 런타임에 필요할 수 있습니다. 표시되는 종속성 포함 크기와 크기 비중은 하드 종속성을 기준으로 합니다.

마이그레이션 감사

Migration Readiness Report는 Dependency Tracer 1.1.0에 포함되어 있습니다. 엔진 마이그레이션 전에 블루프린트 구조를 준비하는 데 도움이 됩니다.

  1. 검사할 블루프린트 계층에 맞게 분석 루트와 제외 항목을 설정하세요.
  2. Migration Audit 탭을 여세요. Run Blueprint Audit 버튼을 클릭하거나 상단의 Scan + audit를 사용하세요.
  3. 검사한 블루프린트 수와 발견한 블루프린트 수, 검사 실패 여부를 확인하세요. Blockers를 먼저 검토한 뒤 Warnings와 Info를 확인하세요.
  4. 발견 항목을 선택해 근거, 고정된 규칙 ID, 블루프린트 구조, 권장 다음 조치를 읽으세요. Open Blueprint 또는 Show in Content Browser로 확인하세요.
  5. 결과를 내보내고 프로젝트에 적합한 변경을 적용하세요. 수동으로 컴파일하고 테스트한 뒤 감사를 다시 실행하세요.

검사 범위부터 확인

  • No Blueprint audit: 최근 일반 스캔에 선택 기능인 감사가 포함되지 않았습니다.
  • No Blueprints in scope: 예상과 다르다면 설정한 루트와 제외 항목을 확인하세요.
  • Inspection failures: 일부 에셋을 읽지 못해 보고서의 검사 범위가 부분적입니다.
  • Completed: 예정된 검사와 분석이 완료되었습니다. 대상 엔진과의 호환성을 입증하는 것은 아닙니다.

블루프린트 검사는 명시적으로 선택해야 실행되며 범위 안의 에셋을 메모리에 로드합니다. 현재 로드된 컴파일 상태를 읽고, 컴파일, 부모 클래스 변경, 재구성, 삭제, 명시적 저장은 실행하지 않습니다. 엔진의 로딩이 메모리 상태에 영향을 줄 수 있지만 감사는 이를 자동으로 저장하거나 기존의 수정됨 플래그를 지우지 않습니다.

프로젝트 복사본에서 실제 엔진 마이그레이션을 테스트하세요. 이 보고서는 현재의 구조적 문제와 검토할 항목을 찾습니다. 새 엔진의 API 변경, 직렬화 변경, C++ 동작, 동적으로 로드되는 참조는 대상 버전에서 별도로 테스트해야 합니다.

임계값은 검토를 알리는 기준이며 호환성 한계가 아닙니다. 프로젝트 구조에 맞게 프로젝트 설정에서 기본값을 변경하세요. 내보내기에는 실제 사용된 값이 기록됩니다.

CSV 및 JSON 내보내기

  1. 스캔을 완료하세요. 내보내기에 마이그레이션 발견 항목이 필요하면 먼저 선택 기능인 블루프린트 감사를 실행하세요.
  2. 상단의 Export 또는 마이그레이션 감사의 Export CSV / Export JSON을 사용하세요.
  3. 인터페이스에서 내보낸 경로를 확인하세요. 마이그레이션 감사의 내보내기 작업은 해당 경로를 클립보드에도 복사합니다.
  4. <Project>/Saved/DependencyTracer/ 또는 Report Export Dir에 설정한 디렉터리에서 파일을 찾으세요.

두 형식 모두 사용 가능한 감사 데이터를 포함한 스캔 보고서를 내보냅니다. 감사 내보내기는 현재 검색이나 심각도 필터에서 보이는 행만 내보내는 것이 아닙니다.

  • CSV: 스프레드시트에서 보고서 섹션을 확인하거나 검토용으로 공유하세요.
  • JSON: 비교나 자체 도구에 사용할 구조화된 스냅샷을 보관하세요.

마이그레이션 데이터에는 검사 범위, 발견 항목, 블루프린트별 지표, 실제 사용된 임계값이 포함됩니다. CSV에는 여러 보고서 섹션이 있으며 JSON은 스키마 버전 1.0을 사용합니다. 두 내보내기 모두 전체 종속성 그래프를 포함하지 않습니다. 범위와 설정이 같은 보고서를 비교하세요. 범위가 바뀌면 합계나 발견 항목도 달라질 수 있습니다.

이후 일반 스캔을 실행하면 기존 감사 결과가 감사가 비활성화된 스캔 결과로 교체됩니다. 취소되거나 실패한 경우 이전에 완료된 보고서를 유지합니다. 에디터를 다시 연 후에는 새 스캔을 실행하세요.

문제 해결

Tools에 Dependency Tracer가 없음

Edit > Plugins에서 플러그인을 활성화하고 다시 시작하세요. 설명 파일이 올바른 플러그인 폴더 바로 아래에 있는지, 패키지가 엔진 버전과 일치하는지 확인하세요. 소스를 수동으로 설치하려면 엔진과 호환되는 C++ 툴체인이 필요하며 에디터 빌드가 성공해야 합니다.

스캔이 비어 있거나 폴더가 누락됨

Analysis Roots와 Excluded Folders를 확인하세요. /Game/Characters 같은 패키지 경로를 사용하세요. 원하는 범위에 플러그인 콘텐츠가 필요하면 활성화한 뒤 새 스캔을 실행하세요.

크기를 알 수 없거나 예상보다 작음

에셋을 저장하고 다시 스캔하세요. 결과는 에셋 레지스트리에서 확인된 디스크상의 패키지 크기를 사용합니다. 저장되지 않았거나 크기를 알 수 없는 항목은 제외될 수 있으며, 탐색이 불완전하면 하한값만 계산될 수 있습니다. 쿠킹된 출력의 크기는 저장된 패키지 크기와 다를 수 있습니다.

미사용 후보가 실제로 게임에서 로드됨

동적 경로와 외부 로딩 시스템을 확인하세요. 관련 폴더를 Additional Root Folders에 추가하고 다시 스캔하세요. 참조 분석은 모든 런타임 문자열 기반 로딩을 추론할 수 없습니다.

종속성 맵에 이전 결과가 표시됨

새 스캔이 끝날 때까지 기다린 뒤 Reload map 버튼을 클릭하세요. 선택한 루트와 하드/소프트 필터를 확인하세요. 표시 제한 때문에 연결이 생략될 수 있습니다. 다른 노드에 초점을 맞춰 더 살펴보세요.

마이그레이션 감사에 감사를 실행하지 않았다고 표시됨

일반 Scan project는 블루프린트 그래프를 검사하지 않습니다. Migration Audit 탭을 열고 Run Blueprint Audit 또는 Scan + audit를 사용하세요.

블루프린트 검사 실패

에셋을 수동으로 열고 누락된 부모 클래스, 제공자, 패키지 문제를 확인하세요. 문제를 해결한 뒤 감사를 다시 실행하세요. 그전까지는 검사 범위가 부분적입니다.

발견 항목이 보이지 않음

검색을 지우고 모든 심각도 필터를 활성화하세요. 검사한 수와 발견한 수, 범위를 확인하세요. 발견 항목 없이 감사가 완료되었다는 것은 현재 규칙에서 아무것도 찾지 못했다는 뜻이며 향후 엔진 마이그레이션을 보증하지 않습니다.

보고서를 내보낼 수 없음

분석이 끝날 때까지 기다리세요. 설정된 출력 디렉터리와 쓰기 권한을 확인한 뒤 Window > Developer Tools > Output Log에서 Dependency Tracer 메시지를 확인하세요.

Unreal에서 모듈 누락 또는 호환되지 않음을 보고함

정확한 엔진 마이너 버전에 맞는 압축 파일을 선택하고 중복 설치된 플러그인이 있는지 확인하세요. 소스 패키지는 호환되는 C++ 툴체인으로 빌드해야 합니다. 다른 엔진 버전의 DLL이 설치 폴더에 섞이지 않도록 하세요.

자주 묻는 질문

플러그인이 에셋을 삭제하거나 다시 작성하나요?

미사용 에셋 페이지는 후보와 에디터 탐색 기능을 제공합니다. 블루프린트 검사는 에셋을 로드하지만 명시적으로 컴파일하거나 저장하지 않습니다. 변경과 정리는 사용자가 별도의 검토 과정에서 수행합니다.

표시된 회수 가능 크기만큼 공간이 확보되나요?

이 값은 검토할 후보의 확인된 패키지 크기입니다. 삭제 전에 사용 여부를 확인하세요. 종속성, 쿠킹, 압축에 따라 배포 빌드에 실제로 포함되는 내용이 달라질 수 있습니다.

가장 큰 루트들의 크기를 합산해도 되나요?

여러 루트가 같은 종속성을 공유할 수 있습니다. 종속성을 포함한 크기를 합산하면 공유 패키지가 반복해서 집계됩니다. 유형별 합계나 실제 측정한 빌드로 다른 관점에서 확인하세요.

감사에서 문제가 없으면 마이그레이션 성공이 보장되나요?

아니요. 보고서는 현재 블루프린트 구조와 로드된 상태를 검토합니다. 실제 대상 엔진에서 프로젝트 복사본을 검증하고 C++ 코드, 제공자, 콘텐츠, 동작을 테스트하세요.

마이그레이션 준비 보고서가 포함되어 있나요?

네. 기존 종속성 및 크기 도구와 함께 Dependency Tracer 1.1.0에 포함되어 있습니다.

패키징한 게임에 Dependency Tracer가 필요한가요?

플러그인 모듈은 에디터 전용입니다. 검사 인터페이스는 패키징한 게임 안에서 실행되지 않습니다.

분석에 온라인 서비스가 필요한가요?

프로젝트 분석은 Unreal Editor에서 로컬로 실행됩니다. CSV와 JSON 보고서는 선택한 로컬 디렉터리에 저장됩니다.

예시 프로젝트와 스크린샷이 내 스캔에 포함되나요?

스크린샷은 예시를 위해 별도로 만든 데모 프로젝트를 보여 줍니다. 사용자의 스캔은 설정된 프로젝트 에셋을 사용합니다. 가이드의 예시 크기와 발견 항목은 플러그인에 미리 삽입된 고정 결과가 아닙니다.

버전 및 지원

이 가이드는 Dependency Tracer 1.1.0과 Windows 64비트의 Unreal Engine 5.5, 5.6, 5.7, 5.8을 다룹니다.

1.1.0에 포함된 기능

종속성 카드와 검사기를 갖춘 Project Atlas 인터페이스, 하드/소프트 참조 경로, 미사용 콘텐츠 분석, 루트별 및 유형별 크기 보고서, CSV/JSON 내보내기, 블루프린트 마이그레이션 준비 보고서가 포함됩니다.

엔진 호환성은 Win64의 UE 5.5.4, 5.6.1, 5.7.4, 5.8.0에서 확인했습니다. 이 릴리스의 검증 환경에서는 Mac과 Linux에서의 실행을 검증하지 않았습니다.
