安装

Dependency Tracer 1.1.0 支持 Windows 64 位平台上的 Unreal Engine 5.5、5.6、5.7 和 5.8。请安装与引擎次版本匹配的插件包。

通过 Fab 安装

  1. 在 Epic Games Launcher 的 Fab 资源库中找到 Dependency Tracer，并为对应的引擎版本安装。
  2. 打开项目。在 Edit > Plugins 中搜索 Dependency Tracer，如有需要则启用它。
  3. 重启编辑器，然后打开 Tools > Dependency Tracer。

从源代码手动安装

  1. 关闭 Unreal Editor。只保留一份插件安装：项目中较旧的副本可能优先于引擎目录中的安装。
  2. 将压缩包中的 DependencyTracer 文件夹放入项目的 Plugins 目录。插件描述文件必须位于下方所示路径。
  3. 源代码包需要与你所用引擎版本完全匹配的受支持 C++ 构建工具。请构建项目的编辑器目标，或在安装前使用 Unreal 的 BuildPlugin 工具构建插件。
  4. 打开项目，如有需要则启用 Dependency Tracer，重启后打开 Tools > Dependency Tracer。

首次扫描

从项目中熟悉的部分开始。先保存已修改的资产，让磁盘上的包大小反映最新保存状态。工作台最初会打开 Dependency Tree；扫描后切换到 Overview。本指南保留英文按钮名称，以便与插件界面对应。

  1. 选择扫描内容。 打开 Project Settings > Plugins > Dependency Tracer。若分析整个项目，将 Analysis Roots 保持为 /Game；也可选择较小的文件夹，例如 /Game/Characters。
  2. 扫描项目。 打开 Tools > Dependency Tracer 并点击 Scan project，等待扫描完成。选择 Scan + audit 或 Run Blueprint Audit 时才会运行可选的蓝图审计。
  3. 从 Overview 开始。 检查扫描的资产数量、内容大小、资产类型及占用最大的根资产。
  4. 追踪较大的资产。 打开 Dependency Tree，使用 Find asset 选择资产，或在内容浏览器中选中资产后点击 Use selected。选择卡片以检查大小和引用。
  5. 审查候选项。 打开 Unused Assets。更改资产之前，使用 Browse 和 Open 确认其用途。
  6. 记录结果。 准备升级时运行 Migration Audit，然后导出 CSV 或 JSON 以供审查。

更改资产或设置后，请重新扫描。如果依赖图提示快照来自较早的扫描，请使用 Reload map。

扫描范围与根资产

范围是要检查的资产集合。根资产是被视为正在使用的起始资产；未使用内容分析会保留通过其硬引用或软引用可到达的资产。

  • Analysis Roots: 纳入分析的内容路径。默认为 /Game。
  • Excluded Folders: 从分析中排除的路径，即使它位于已纳入的文件夹内。
  • Additional Root Folders: 其中的资产应视为正在使用的文件夹，包括游戏动态加载的内容。
  • Include Plugin Content / Include Engine Content: 可选的扫描范围扩展。两项默认均关闭。

请使用 /Game/Characters 这样的 Unreal 包路径。Windows 文件夹路径不适用。受支持的关卡、打包和资产管理配置也会提供根资产。范围内的所有关卡均视为根资产。如果打包配置启用了 Cook All，范围内的全部资产都会视为正在使用，未使用列表可能为空。

Additional Root Folders 会添加需要保留的根资产，但不会扩大扫描范围。如果要完整分析某个文件夹的内容，也应将它加入 Analysis Roots。

明确指定动态内容。 C++ 中拼接的路径、从文件读取的字符串或外部运行时系统可能不会作为资产注册表引用出现。请将相应文件夹加入 Additional Root Folders，并核实游戏的加载路径。

扫描器会使用完整的资产注册表再次检查孤立候选项，包括所选范围之外的引用。这可以提高结果的可信度，但无法发现所有运行时动态引用。

项目概览

Overview 汇总最近一次已完成的扫描。可从这里选择需要重点关注的资产类别或根资产。

  • Scanned content: 配置范围内已知的磁盘包大小，以及资产数量和跳过数量。
  • Size by asset type: 按已知扫描字节总量中的占比，展示体积最大的资产类型。
  • Largest root footprints: 硬引用依赖闭包占用较大的根资产。
  • Unused summary: 候选项数量、需手动审查的数量和可能回收的体积。可能回收的体积仅汇总最终归类为 Safe to delete 的候选项的已知大小。

大小未知的包不会计入已知大小总量。这些数值反映扫描范围，并非整个项目文件夹的大小。

未使用资产

审查从检测到的正在使用的根资产无法到达的资产。每个条目包含资产类型、已知直接大小、可信度以及引用它的资产数量。

构建体积

使用 Top roots 分析含依赖的硬引用占用较大的根资产。使用 By type 查看哪些资产类型占据最多的已知包字节。

资产的直接大小与含依赖大小
数值含义
直接大小该资产自身包已保存且已知的大小。
含硬依赖大小根资产自身的包加上所有可到达的硬依赖；在该根资产的占用计算中，每个包只计一次。
共享依赖同一个包可能同时包含在多个根资产的占用中。将这些占用相加会重复计算共享资产。
未知或不完整的大小报告中的已知数值可能只是下限。≥ 标记表示计算尚不完整。

大小查询优先使用资产注册表中的包大小，无法取得时则使用已保存包文件的文件系统大小。这些大小只是构建体积的估计依据。Cook、压缩、目标平台及打包设置均可能导致发布体积不同。需要实际交付体积时，请测量经过 Cook 的构建。

依赖树

  1. 使用 Find asset 选择根资产，或在内容浏览器中选择资产后点击 Use selected，也可输入包路径并点击 Load map。
  2. 选择 Dependencies 追踪它所引用的资产，或选择 Referencers 分析引用它的资产。
  3. 使用 Hard + Soft、Hard only 或 Soft only 筛选依赖图。
  4. 选择一张卡片。在右侧检查器中查看直接大小、含依赖大小、引用计数、可见依赖的体积占比，以及已记录的迁移审计结果。
  5. 使用 Open Blueprint 或 Open asset、Show in browser、Copy path 和 Focus asset 继续分析。

理解连接线

黄铜色实线表示硬引用。蓝灰色虚线表示软引用。无论查看依赖项还是引用者，箭头都沿实际引用方向指向。圆点表示共享分支；虚线路径在交叉处的缺口并不表示连接。

软引用可以避免直接硬依赖，但通过软引用加载的资产在运行时仍可能不可或缺。显示的含依赖大小和体积分布仅涉及硬依赖。

迁移审计

Migration Readiness Report 包含在 Dependency Tracer 1.1.0 中，可帮助你在引擎迁移前整理蓝图结构。

  1. 为要检查的蓝图层配置分析根路径和排除项。
  2. 打开 Migration Audit。点击 Run Blueprint Audit，或使用页眉中的 Scan + audit。
  3. 查看已检查/已发现的蓝图数量及检查失败情况。先审查 Blockers，再查看 Warnings 和 Info。
  4. 选择一个发现项，查看其依据、稳定规则 ID、蓝图结构及建议的下一步。使用 Open Blueprint 或 Show in Content Browser 进行检查。
  5. 导出结果，实施适合项目的更改，手动编译并测试，然后再次运行审计。

先查看覆盖情况

  • No Blueprint audit: 最近一次常规扫描未包含可选审计。
  • No Blueprints in scope: 如果与预期不符，请检查配置的根路径和排除项。
  • Inspection failures: 部分资产无法读取；报告仅覆盖部分内容。
  • Completed: 已安排的检查与分析完成。这并不能证明与目标引擎兼容。

蓝图检查需要主动选择，并会将范围内的资产加载到内存。它读取当前已加载的编译状态，不会执行编译、重新指定父类、重建、删除或显式保存。引擎加载可能影响内存中的状态；审计不会在后台保存这些变化，也不会清除已有的未保存标记。

在项目副本中测试实际的引擎迁移。 此报告查找当前结构问题，并提示需要审查的内容。新引擎的 API 变化、序列化变化、C++ 行为以及动态加载的引用仍需在目标版本中测试。

CSV 与 JSON 导出

  1. 等待扫描完成。如果导出中需要迁移发现项，请先运行可选的蓝图审计。
  2. 使用页眉中的 Export，或迁移审计中的 Export CSV / Export JSON。
  3. 在界面中查看导出路径。迁移审计中的导出操作还会将该路径复制到剪贴板。
  4. 在 <Project>/Saved/DependencyTracer/，或 Report Export Dir 配置的目录中查找文件。

两种格式都会导出扫描报告及其中可用的审计数据。审计导出不限于当前搜索或严重程度筛选后可见的行。

  • CSV: 在电子表格中查看报告各部分，或分享给他人审查。
  • JSON: 保存结构化快照，便于比较或供自定义工具使用。

迁移数据包含覆盖情况、发现项、逐个蓝图的指标及实际使用的阈值。CSV 包含多个报告部分；JSON 使用 1.0 版数据结构。两种导出都不包含完整依赖图。请在相同范围和设置下比较报告；范围变化可能导致总量或发现项发生变化。

后续的常规扫描会用未启用审计的扫描结果替换原有审计结果。取消或失败时会保留此前已完成的报告。重新打开编辑器后，请运行一次新扫描。

故障排查

Tools 菜单中找不到 Dependency Tracer

在 Edit > Plugins 中启用插件并重启。检查描述文件是否直接位于正确的插件文件夹中，并确认插件包与引擎版本匹配。手动安装源代码需要与引擎兼容的 C++ 工具链，并成功构建编辑器目标。

扫描结果为空或缺少文件夹

检查 Analysis Roots 和 Excluded Folders。使用 /Game/Characters 这样的包路径。如果需要分析插件内容，请启用相应选项，然后重新扫描。

大小未知或比预期小

保存资产后重新扫描。结果使用资产注册表中已知的磁盘包大小。未保存或大小未知的包可能被省略；遍历不完整时可能只得到下限。Cook 后的输出可能与已保存包大小不同。

未使用候选资产实际上会被游戏加载

检查动态路径和外部加载系统。将相关文件夹加入 Additional Root Folders 后重新扫描。引用分析无法推断所有运行时基于字符串的加载。

依赖图仍显示旧结果

等待新扫描完成后点击 Reload map。检查当前根资产及硬/软引用筛选条件。显示限制可能省略连接；可聚焦其他节点进一步分析。

迁移审计提示尚未运行审计

常规 Scan project 不检查蓝图图表。打开 Migration Audit 并使用 Run Blueprint Audit 或 Scan + audit。

蓝图检查失败

手动打开资产，检查缺失的父类、提供方及包问题。解决后重新运行审计。在此之前，报告覆盖范围仍不完整。

看不到任何发现项

清除搜索条件并启用所有严重程度筛选项。检查已检查/已发现的数量及范围。审计完成且无发现项，仅表示当前规则未发现问题；这不能认证未来的引擎迁移会成功。

报告无法导出

等待分析完成。检查配置的输出目录和写入权限，然后在 Window > Developer Tools > Output Log 中查看 Dependency Tracer 消息。

Unreal 提示模块缺失或不兼容

选择与引擎次版本完全匹配的压缩包，并检查是否重复安装插件。源代码包必须使用兼容的 C++ 工具链构建。不要在安装中混入其他引擎版本的 DLL。

常见问题

插件会删除或改写我的资产吗？

未使用资产页面提供候选项和编辑器导航操作。蓝图检查会加载资产，但不会显式编译或保存。修改和清理仍需在你自己的审查流程中另行进行。

显示的可能回收体积能保证实际节省空间吗？

它表示待审查候选项的已知包大小。删除任何内容前，请确认其用途。依赖关系、Cook 和压缩都会影响发布构建实际包含的内容。

可以将最大的根资产大小相加吗？

多个根资产可能共享相同依赖。将含依赖大小相加会重复计算共享包；可以参考按类型汇总的总量，或测量实际构建，从另一个角度评估体积。

没有发现问题的审计能保证迁移成功吗？

不能。报告审查的是当前蓝图结构和已加载状态。请在实际目标引擎中验证项目副本，并测试 C++ 代码、提供方、内容和行为。

是否包含迁移就绪报告？

是。它与现有的依赖和体积工具一同包含在 Dependency Tracer 1.1.0 中。

打包后的游戏需要 Dependency Tracer 吗？

插件模块仅供编辑器使用。检查界面不会在打包后的游戏中运行。

分析需要在线服务吗？

项目分析在本地 Unreal Editor 中运行。CSV 和 JSON 报告写入所选的本地目录。

示例项目和截图属于我的扫描结果吗？

截图展示的是专门创建的演示项目。你的扫描使用你所配置的项目资产。指南中的示例大小与发现项并不是预先插入插件的结果。

版本与支持

本指南适用于 Dependency Tracer 1.1.0，支持 Windows 64 位上的 Unreal Engine 5.5、5.6、5.7 和 5.8。

1.1.0 包含的功能

Project Atlas 界面包含依赖卡片和检查器、硬/软引用路径、未使用内容分析、根资产和资产类型体积报告、CSV/JSON 导出，以及蓝图迁移就绪报告。

已在 Win64 平台使用 UE 5.5.4、5.6.1、5.7.4 和 5.8.0 检查引擎兼容性。本版本的验证环境未验证 Mac 和 Linux 上的运行情况。
