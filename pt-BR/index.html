Relatório de preparação para a migração
Leia os resultados como uma fila de revisão. Os tamanhos dos pacotes são estimativas baseadas em recursos salvos, as entradas não utilizadas são candidatas e o relatório de migração é uma auditoria estrutural. Use as evidências para decidir o que alterar e depois teste seu projeto.

Instalação

O Dependency Tracer 1.1.0 oferece suporte ao Unreal Engine 5.5, 5.6, 5.7 e 5.8 no Windows de 64 bits. Instale o pacote correspondente à versão secundária do seu motor.

Instalação pelo Fab

  1. Encontre o Dependency Tracer na sua biblioteca do Fab no Epic Games Launcher e instale-o para o motor correspondente.
  2. Abra seu projeto. Em Edit > Plugins, procure Dependency Tracer e ative-o, se necessário.
  3. Reinicie o editor e abra Tools > Dependency Tracer.

Instalação manual a partir do código-fonte

  1. Feche o Unreal Editor. Mantenha uma única instalação do plugin: uma cópia antiga no projeto pode ter prioridade sobre uma instalação no motor.
  2. Coloque a pasta DependencyTracer do arquivo no diretório Plugins do seu projeto. O descritor deve estar no caminho mostrado abaixo.
  3. Um pacote de código-fonte exige as ferramentas de compilação C++ compatíveis com a versão exata do seu motor. Compile o alvo de editor do projeto ou compile o plugin com a ferramenta BuildPlugin do Unreal antes de instalá-lo.
  4. Abra o projeto, ative Dependency Tracer se necessário, reinicie e abra Tools > Dependency Tracer.

Os arquivos de código-fonte enviados e a instalação processada pelo Fab correspondem a etapas diferentes de distribuição. Um arquivo de código-fonte instalado manualmente pode solicitar compilação; uma DLL compilada para uma versão secundária do motor não pode ser reutilizada em outra.

Sua primeira varredura

Comece por uma parte conhecida do seu projeto. Salve primeiro os recursos alterados para que os tamanhos dos pacotes em disco representem o último estado salvo. O painel abre inicialmente Dependency Tree; mude para Overview após a varredura. Este guia mantém os rótulos dos botões em inglês para corresponder à interface do plugin.

  1. Escolha o conteúdo que deseja varrer. Abra Project Settings > Plugins > Dependency Tracer. Deixe Analysis Roots em /Game para o projeto ou escolha uma pasta menor, como /Game/Characters.
  2. Faça a varredura do projeto. Abra Tools > Dependency Tracer e clique em Scan project. Aguarde a conclusão da varredura. A auditoria opcional de Blueprints é executada quando você escolhe Scan + audit ou Run Blueprint Audit.
  3. Comece por Overview. Confira a quantidade de recursos analisados, os tamanhos do conteúdo, os tipos de recursos e as maiores pegadas das raízes.
  4. Siga um recurso pesado. Abra Dependency Tree, escolha-o com Find asset ou selecione-o no navegador de conteúdo e clique em Use selected. Selecione cartões para inspecionar seus tamanhos e referências.
  5. Revise os candidatos. Abra Unused Assets. Use Browse e Open para verificar a finalidade de um recurso antes de alterá-lo.
  6. Registre o resultado. Execute Migration Audit ao preparar uma atualização e depois exporte CSV ou JSON para revisão.

Se alterar recursos ou configurações, execute uma nova varredura. Use Reload map quando o mapa indicar que seu instantâneo vem de uma varredura anterior.

Escopo e raízes da varredura

O escopo é o conjunto de recursos a inspecionar. Uma raiz é um recurso inicial tratado como ativo; a análise de conteúdo não utilizado preserva os recursos alcançáveis por suas referências rígidas ou suaves.

  • Analysis Roots: caminhos de conteúdo incluídos na análise. O padrão é /Game.
  • Excluded Folders: caminhos excluídos da análise, mesmo quando estão dentro de uma pasta incluída.
  • Additional Root Folders: pastas cujos recursos devem ser considerados ativos, incluindo conteúdo carregado dinamicamente pelo jogo.
  • Include Plugin Content / Include Engine Content: expansão opcional do escopo. Ambas as opções ficam desativadas por padrão.

Use caminhos de pacotes do Unreal, como /Game/Characters, em vez de caminhos de pastas do Windows. As raízes também vêm das configurações compatíveis de mapas, empacotamento e gerenciamento de recursos. Todos os mapas no escopo são tratados como raízes. Se Cook All estiver ativado na configuração de empacotamento, todos os recursos no escopo estarão ativos e a lista de recursos não utilizados poderá ficar vazia.

Additional Root Folders adiciona raízes de preservação; não amplia o escopo da varredura. Inclua a pasta também em Analysis Roots quando quiser analisar todo o seu conteúdo.

Declare explicitamente o conteúdo dinâmico. Caminhos montados em C++, strings lidas de um arquivo ou sistemas externos de execução podem não aparecer como referências do Asset Registry. Adicione as pastas apropriadas a Additional Root Folders e verifique os caminhos de carregamento do jogo.

O scanner verifica novamente os candidatos isolados no Asset Registry completo, incluindo referências externas ao escopo escolhido. Isso aumenta a confiança, mas não permite descobrir todas as referências dinâmicas em tempo de execução.

Visão geral do projeto

Overview resume a última varredura concluída. Comece aqui para escolher qual família de recursos ou raiz merece atenção.

  • Conteúdo analisado: tamanhos conhecidos dos pacotes em disco no escopo configurado, com contagens de recursos e itens ignorados.
  • Tamanho por tipo de recurso: os maiores tipos, ponderados pela participação nos bytes conhecidos da varredura.
  • Maiores pegadas das raízes: raízes com conjuntos transitivos de dependências por referências rígidas de grande tamanho.
  • Resumo de recursos não utilizados: quantidade de candidatos, quantidade que exige revisão manual e espaço potencialmente recuperável. Esse espaço soma os tamanhos conhecidos dos candidatos finais classificados como Safe to delete.

Os tamanhos desconhecidos de pacotes são omitidos dos totais de tamanhos conhecidos. Esses números representam o escopo da varredura; não são o tamanho da pasta completa do projeto.

Recursos não utilizados

Revise os recursos que não são alcançáveis a partir das raízes ativas detectadas. Cada entrada inclui o tipo de recurso, o tamanho direto conhecido, a confiança e a quantidade de recursos que o referenciam.

Tamanho da compilação

Use Top roots para investigar raízes com grandes pegadas inclusivas de referências rígidas. Use By type para ver quais tipos de recursos representam a maior quantidade de bytes conhecidos de pacotes.

Tamanhos diretos e inclusivos dos recursos
ValorSignificado
Tamanho diretoO tamanho salvo conhecido do pacote próprio desse recurso.
Tamanho inclusivo de referências rígidasO pacote próprio da raiz e suas dependências rígidas alcançáveis, contando cada pacote uma única vez dentro dessa pegada.
Dependências compartilhadasO mesmo pacote pode pertencer às pegadas de várias raízes. Somar essas pegadas conta os recursos compartilhados mais de uma vez.
Tamanho desconhecido ou incompletoO valor conhecido informado pode ser um limite inferior. Um marcador ≥ significa que o cálculo está incompleto.

A consulta de tamanho usa primeiro os tamanhos de pacotes do Asset Registry e, como alternativa, o tamanho do arquivo do pacote salvo no sistema de arquivos. Esses tamanhos servem como aproximação do peso da compilação. O processamento do conteúdo (cooking), a compressão, a plataforma de destino e as configurações de empacotamento podem gerar um tamanho final diferente. Meça uma compilação com o conteúdo processado quando precisar do tamanho real de distribuição.

Árvore de dependências

  1. Escolha uma raiz com Find asset, selecione um recurso no navegador de conteúdo e clique em Use selected, ou digite seu caminho de pacote e clique em Load map.
  2. Escolha Dependencies para seguir os recursos que ela referencia ou Referencers para investigar os recursos que a referenciam.
  3. Filtre o mapa com Hard + Soft, Hard only ou Soft only.
  4. Selecione um cartão. Leia os tamanhos direto e inclusivo, os contadores de referências, o peso das dependências visíveis e os achados de migração registrados no inspetor à direita.
  5. Use Open Blueprint ou Open asset, Show in browser, Copy path e Focus asset para continuar a investigação.

Interprete as linhas

As linhas contínuas na cor de latão são referências rígidas. As linhas tracejadas em cinza-azulado são referências suaves. As setas seguem a direção real da referência tanto na visão de dependências quanto na de referenciadores. Os pontos identificam bifurcações compartilhadas; uma lacuna em uma rota tracejada em um cruzamento não é uma conexão.

As referências suaves podem evitar uma dependência rígida direta, mas os recursos carregados por elas ainda podem ser necessários em tempo de execução. O tamanho inclusivo e a distribuição de peso exibidos dizem respeito às dependências rígidas.

Auditoria de migração

O Migration Readiness Report está incluído no Dependency Tracer 1.1.0. Ele ajuda a preparar a estrutura dos seus Blueprints antes de uma migração do motor.

  1. Configure as raízes de análise e as exclusões para a camada de Blueprints que deseja inspecionar.
  2. Abra Migration Audit. Clique em Run Blueprint Audit ou use Scan + audit no cabeçalho.
  3. Leia a contagem de inspecionados/encontrados e eventuais falhas de inspeção. Revise primeiro Blockers, depois Warnings e Info.
  4. Selecione um achado para ler suas evidências, o ID estável da regra, a estrutura do Blueprint e a próxima etapa recomendada. Use Open Blueprint ou Show in Content Browser para inspecioná-lo.
  5. Exporte o resultado, faça as alterações adequadas ao projeto, compile e teste manualmente e execute a auditoria novamente.

Leia primeiro a cobertura

  • No Blueprint audit: a última varredura normal não incluiu a auditoria opcional.
  • No Blueprints in scope: verifique as raízes e exclusões configuradas se esse resultado for inesperado.
  • Inspection failures: alguns recursos não puderam ser lidos; o relatório tem cobertura parcial.
  • Completed: a inspeção e a análise programadas foram concluídas. Isso não comprova compatibilidade com um motor de destino.

A inspeção de Blueprints é opcional e carrega na memória os recursos dentro do escopo. Ela lê o status atual de compilação já carregado; não inicia a compilação, troca a classe pai, reconstrói, exclui nem salva explicitamente esses recursos. O carregamento pelo motor pode afetar o estado em memória, e a auditoria não o salva silenciosamente nem limpa um indicador de alterações pendentes existente.

Teste a migração real do motor em uma cópia do projeto. Este relatório encontra problemas estruturais atuais e pontos que merecem revisão. Alterações na API do novo motor, mudanças de serialização, o comportamento do C++ e referências carregadas dinamicamente ainda precisam ser testados na versão de destino.

Referência das regras de auditoria

Os bloqueios identificam um problema atual ou uma lacuna na auditoria de preparação. Os avisos incluem heurísticas estruturais que merecem revisão. As informações identificam provedores a verificar para o motor de destino.

O acoplamento exclui autorreferências. As verificações de acoplamento e ciclos usam conexões rígidas diretas entre Blueprints dentro do escopo auditado; conexões suaves, Blueprints fora do escopo e conexões por outros tipos de recursos ficam fora dessas verificações. Classes nativas não são contadas como ancestrais de Blueprint. As verificações de provedores de plugins também inspecionam classes pai nativas e chamadas.

Um limiar indica que algo merece revisão; não é um limite de compatibilidade. Altere os valores padrão nas configurações do projeto para adequá-los à sua arquitetura; as exportações registram os valores realmente usados.

Exportações CSV e JSON

  1. Conclua a varredura. Execute primeiro a auditoria opcional de Blueprints se precisar dos achados de migração na exportação.
  2. Use Export no cabeçalho ou Export CSV / Export JSON em Migration Audit.
  3. Leia o caminho exportado na interface. As ações de exportação de Migration Audit também copiam esse caminho para a área de transferência.
  4. Encontre os arquivos em <Project>/Saved/DependencyTracer/ ou no diretório configurado em Report Export Dir.

Os dois formatos exportam o relatório da varredura, incluindo seus dados de auditoria disponíveis. Uma exportação de auditoria não se limita às linhas visíveis com a busca ou o filtro de gravidade atuais.

  • CSV: inspecione as seções do relatório em uma planilha ou compartilhe-as para revisão.
  • JSON: mantenha um instantâneo estruturado para comparações ou suas próprias ferramentas.

Os dados de migração incluem cobertura, achados, métricas por Blueprint e os limiares realmente usados. O CSV contém várias seções do relatório; o JSON usa a versão 1.0 do esquema. Nenhuma exportação inclui o grafo completo de dependências. Compare relatórios com o mesmo escopo e as mesmas configurações; mudanças de escopo podem explicar alterações nos totais ou nos achados.

Uma varredura normal posterior substitui o resultado da auditoria por uma varredura com a auditoria desativada. Cancelamentos ou falhas preservam o relatório concluído anterior. Após reabrir o editor, execute uma nova varredura.

Solução de problemas

O Dependency Tracer não aparece em Tools

Ative o plugin em Edit > Plugins e reinicie. Confira se o descritor está diretamente na pasta correta do plugin e se o pacote corresponde à versão do motor. Uma instalação manual a partir do código-fonte exige um conjunto de ferramentas C++ compatível com o motor e uma compilação bem-sucedida do editor.

A varredura está vazia ou não inclui uma pasta

Confira Analysis Roots e Excluded Folders. Use um caminho de pacote como /Game/Characters. Ative o conteúdo de plugins se o escopo desejado exigir e execute uma nova varredura.

Um tamanho é desconhecido ou menor que o esperado

Salve o recurso e faça uma nova varredura. O resultado usa tamanhos conhecidos de pacotes em disco do Asset Registry. Tamanhos não salvos ou desconhecidos podem ser omitidos; uma travessia incompleta pode produzir um limite inferior. A saída do processamento do conteúdo pode ser diferente dos tamanhos de pacotes salvos.

Meu jogo carrega um candidato marcado como não utilizado

Verifique os caminhos dinâmicos e os sistemas externos de carregamento. Adicione as pastas relevantes a Additional Root Folders e faça uma nova varredura. A análise de referências não consegue inferir todos os carregamentos baseados em strings em tempo de execução.

O mapa de dependências mostra resultados antigos

Aguarde a conclusão da nova varredura e clique em Reload map. Confira a raiz selecionada e o filtro de referências rígidas/suaves. Os limites de exibição podem omitir conexões; foque outro nó para explorar mais.

A auditoria de migração informa que nenhuma auditoria foi executada

Uma Scan project normal não inspeciona grafos de Blueprints. Abra Migration Audit e use Run Blueprint Audit ou Scan + audit.

A inspeção de um Blueprint falhou

Abra o recurso manualmente e verifique classes pai ausentes, provedores e problemas no pacote. Resolva-os e execute a auditoria novamente. Até lá, a cobertura é parcial.

Nenhum achado está visível

Limpe a busca e ative todos os filtros de gravidade. Confira a contagem de inspecionados/encontrados e o escopo. Uma auditoria concluída sem achados significa que suas regras atuais não encontraram nenhum; isso não certifica uma futura migração do motor.

Não foi possível exportar um relatório

Aguarde a conclusão da análise. Verifique o diretório de saída configurado e as permissões de gravação e leia Window > Developer Tools > Output Log para encontrar as mensagens do Dependency Tracer.

O Unreal informa que há módulos ausentes ou incompatíveis

Escolha o arquivo para a versão secundária exata do motor e confira se há instalações duplicadas do plugin. Pacotes de código-fonte devem ser compilados com um conjunto de ferramentas C++ compatível. Não inclua DLLs de outra versão do motor na instalação.

Perguntas frequentes

O plugin exclui ou reescreve meus recursos?

Unused Assets apresenta candidatos e ações de navegação do editor. A inspeção de Blueprints carrega recursos, mas não os compila nem salva explicitamente. As alterações e a limpeza fazem parte do seu processo de revisão separado.

O espaço recuperável exibido garante economia de espaço?

É o tamanho conhecido dos pacotes de candidatos a revisar. Verifique o uso deles antes de excluir qualquer coisa. As dependências, o processamento do conteúdo e a compressão podem afetar o que uma compilação distribuída realmente contém.

Posso somar os tamanhos das maiores raízes?

Várias raízes podem compartilhar as mesmas dependências. Somar seus tamanhos inclusivos conta esses pacotes compartilhados repetidamente; use os totais por tipo ou uma compilação medida para ter outra perspectiva.

Uma auditoria sem problemas garante que a migração funcionará?

Não. O relatório revisa a estrutura atual dos Blueprints e seu estado carregado. Valide uma cópia do projeto no motor de destino real e teste o código C++, os provedores, o conteúdo e o comportamento.

O relatório de preparação para a migração está incluído?

Sim. Ele está incluído no Dependency Tracer 1.1.0 junto com as ferramentas existentes de dependências e tamanhos.

Meu jogo empacotado precisa do Dependency Tracer?

O módulo do plugin é exclusivo do editor. Sua interface de inspeção não é executada dentro do jogo empacotado.

A análise exige um serviço online?

A análise do projeto é executada localmente no Unreal Editor. Os relatórios CSV e JSON são gravados no diretório local escolhido.

O projeto de exemplo e as capturas fazem parte da minha varredura?

As capturas mostram um projeto de demonstração criado de propósito. Sua varredura usa os recursos configurados do seu projeto. Os tamanhos e achados de exemplo do guia não são resultados predefinidos inseridos no plugin.

Versão e suporte

Este guia cobre o Dependency Tracer 1.1.0 para Unreal Engine 5.5, 5.6, 5.7 e 5.8 no Windows de 64 bits.

O que está incluído na versão 1.1.0

A interface Project Atlas com cartões de dependências e inspetor, rotas de referências rígidas/suaves, investigação de conteúdo não utilizado, relatórios de tamanho por raiz e tipo, exportação CSV/JSON e o relatório de preparação para a migração de Blueprints.

A compatibilidade do motor foi verificada com UE 5.5.4, 5.6.1, 5.7.4 e 5.8.0 no Win64. A execução no Mac e no Linux não foi verificada no ambiente de validação desta versão.

Relate um problema

Entre em contato pelo endereço nexusforgeuesupport@gmail.com.

Inclua as versões do Unreal Engine e do plugin, a aba selecionada, as raízes e exclusões da varredura, a mensagem exata e os passos para reproduzir o problema.
