インストール

Dependency Tracer 1.1.0 は、Windows 64 ビットの Unreal Engine 5.5、5.6、5.7、5.8 に対応しています。お使いのエンジンのマイナーバージョンに合ったパッケージをインストールしてください。

Fab からインストールする

  1. Epic Games Launcher の Fab ライブラリで Dependency Tracer を探し、対応するエンジンにインストールします。
  2. プロジェクトを開きます。Edit > Plugins で Dependency Tracer を検索し、必要に応じて有効にします。
  3. エディタを再起動し、Tools > Dependency Tracer を開きます。

ソースから手動でインストールする

  1. Unreal Editor を閉じます。プラグインのインストールは 1 つだけ残してください。プロジェクト内の古いコピーが、エンジン側のインストールより優先されることがあります。
  2. アーカイブ内の DependencyTracer フォルダを、プロジェクトの Plugins ディレクトリに配置します。ディスクリプタは、以下に示すパスに置く必要があります。
  3. ソースパッケージには、使用中のエンジンの正確なバージョンでサポートされる C++ ビルドツールが必要です。プロジェクトのエディタターゲットをビルドするか、Unreal の BuildPlugin ツールでプラグインをビルドしてからインストールします。
  4. プロジェクトを開き、必要に応じて Dependency Tracer を有効にします。再起動して Tools > Dependency Tracer を開きます。

初めてのスキャン

まずはプロジェクトのよく知っている部分から始めます。変更したアセットを先に保存し、ディスク上のパッケージサイズが最新の保存状態を反映するようにします。ワークベンチは最初に Dependency Tree を開きます。スキャン後に Overview へ切り替えてください。このガイドでは、プラグインの UI と照合できるようにボタン名を英語のまま記載しています。

  1. スキャンするコンテンツを選びます。 Project Settings > Plugins > Dependency Tracer を開きます。プロジェクト全体なら Analysis Roots を /Game のままにするか、/Game/Characters などの小さなフォルダを選びます。
  2. プロジェクトをスキャンします。 Tools > Dependency Tracer を開き、Scan project をクリックして、完了を待ちます。任意の Blueprint 監査は、Scan + audit または Run Blueprint Audit を選ぶと実行されます。
  3. まず Overview を確認します。 スキャンしたアセット数、コンテンツサイズ、アセットの種類、占有サイズが大きいルートを確認します。
  4. サイズの大きいアセットをたどります。 Dependency Tree を開き、Find asset で選ぶか、コンテンツブラウザでアセットを選択して Use selected をクリックします。カードを選ぶと、サイズと参照を確認できます。
  5. 候補を確認します。 Unused Assets を開きます。変更する前に、Browse と Open でアセットの用途を確認します。
  6. 結果を記録します。 アップグレードの準備では Migration Audit を実行し、確認用に CSV または JSON をエクスポートします。

アセットや設定を変更したら、再度スキャンしてください。マップのスナップショットが以前のスキャンに基づくと表示されたら、Reload map を使います。

スキャン範囲とルート

範囲は、調査するアセットの集合です。ルートは、使用中とみなす起点のアセットです。未使用コンテンツの分析では、ルートからハード参照またはソフト参照で到達できるアセットを保持します。

  • Analysis Roots: 分析に含めるコンテンツパスです。既定値は /Game です。
  • Excluded Folders: 分析から除外するパスです。含めたフォルダの内部にあっても除外されます。
  • Additional Root Folders: 内部のアセットを使用中とみなすフォルダです。ゲームが動的に読み込むコンテンツも含めます。
  • Include Plugin Content / Include Engine Content: 必要に応じて範囲を広げる設定です。どちらも既定ではオフです。

/Game/Characters などの Unreal パッケージパスを使用してください。Windows のフォルダパスは使えません。対応するマップ、パッケージ化、アセット管理の設定からもルートが取得されます。範囲内のすべてのマップはルートとして扱います。パッケージ化の設定で Cook All が有効なら、範囲内の全アセットを使用中とみなすため、未使用一覧が空になることがあります。

Additional Root Folders は保持対象のルートを追加しますが、スキャン範囲は広げません。フォルダ内のコンテンツをすべて分析する場合は、そのフォルダを Analysis Roots にも含めてください。

動的なコンテンツは明示してください。 C++ で組み立てるパス、ファイルから読み取る文字列、外部の実行時システムは、アセットレジストリの参照に現れない場合があります。該当フォルダを Additional Root Folders に追加し、ゲームの読み込み経路を確認してください。

スキャナは、範囲外からの参照も含め、アセットレジストリ全体で孤立した候補を再確認します。これにより確度は高まりますが、実行時の動的な参照をすべて検出できるわけではありません。

プロジェクト概要

Overview は、直近で完了したスキャンをまとめます。まずここで、注目すべきアセットの種類やルートを選びます。

  • Scanned content: 設定した範囲内の、既知のディスク上のパッケージサイズと、アセット数、スキップ数です。
  • Size by asset type: スキャンで確認できた総バイト数に占める割合で、サイズの大きいアセットの種類を示します。
  • Largest root footprints: ハード参照で到達できる依存先全体の占有サイズが大きいルートです。
  • Unused summary: 候補数、手動確認が必要な件数、回収可能サイズです。回収可能サイズには、最終的に Safe to delete に分類された候補の既知サイズだけを合計します。

サイズが不明なパッケージは、既知サイズの合計から除外されます。これらの数値はスキャン範囲を表し、プロジェクトフォルダ全体のサイズではありません。

未使用アセット

検出した使用中のルートから到達できないアセットを確認します。各項目には、アセットの種類、既知の直接サイズ、確度、参照元の数が表示されます。

未使用アセットの確度
フィルタ意味確認方法
Safe to deleteレジストリでの確認後も参照元が検出されなかった、孤立した候補です。Unreal の通常のアセットツールで削除する前に、用途と動的な使用の有無を確認します。
Review manuallyさらに確認が必要なアセットです。たとえば、依存関係の島から参照されている場合や、そのクラスが保護対象の場合です。関連アセットと読み込みコードを調べます。依存関係の島は、まとまり全体で確認してください。

Browse でアセットの場所を表示し、Open で調べ、Copy path でパッケージパスを共有します。Keep Asset Classes は、指定したクラスが Safe to delete に分類されることを防ぎます。

このタブは確認用の一覧を表示し、アセットを自動で削除しません。手動で整理した後は、影響を受けるマップと読み込み経路をテストし、再度スキャンしてください。

ビルドサイズ

Top roots で、ハード参照の依存先を含む占有サイズが大きいルートを調べます。By type では、既知のパッケージ容量を多く占めるアセットの種類を確認します。

アセットの直接サイズと依存先を含むサイズ
値意味
直接サイズそのアセット自身の保存済みパッケージの既知サイズです。
ハード依存先を含むサイズルート自身のパッケージと、ハード参照で到達できる依存先の合計です。そのルートの占有サイズ内では、各パッケージを 1 回だけ数えます。
共有する依存先同じパッケージが複数のルートの占有サイズに含まれることがあります。それらを合計すると、共有アセットを重複して数えます。
不明または不完全なサイズ報告される既知の値は下限にとどまる場合があります。≥ マークは、計算が不完全であることを示します。

サイズはまずアセットレジストリのパッケージサイズから取得し、取得できない場合は保存済みパッケージファイルのファイルシステム上のサイズを使います。これらはビルドの重さを推測する目安です。クック、圧縮、対象プラットフォーム、パッケージ化の設定により、配布サイズは変わります。実際の配布サイズが必要な場合は、クック済みビルドを測定してください。

依存関係ツリー

  1. Find asset でルートを選ぶか、コンテンツブラウザでアセットを選択して Use selected をクリックします。パッケージパスを入力して Load map をクリックすることもできます。
  2. Dependencies を選ぶと、そのアセットが参照する依存先をたどれます。Referencers を選ぶと、そのアセットを参照する参照元を調べられます。
  3. Hard + Soft、Hard only、Soft only でマップを絞り込みます。
  4. カードを選択します。右側のインスペクタで、直接サイズ、依存先を含むサイズ、参照数、表示中の依存先のサイズ比率、記録された移行監査の検出事項を確認します。
  5. Open Blueprint または Open asset、Show in browser、Copy path、Focus asset を使って調査を続けます。

線の意味を読み取る

真鍮色の実線はハード参照、青灰色の破線はソフト参照です。依存先と参照元のどちらの表示でも、矢印は実際の参照方向を示します。点は共有する分岐を表します。交差部分の破線の切れ目は接続点ではありません。

ソフト参照を使うと直接のハード依存を避けられますが、ソフト参照で読み込むアセットも実行時に必要な場合があります。表示される依存先を含むサイズとサイズ内訳は、ハード依存を対象としています。

移行監査

Migration Readiness Report は Dependency Tracer 1.1.0 に含まれています。エンジン移行前に Blueprint の構造を整えるためのレポートです。

  1. 調べたい Blueprint 層に合わせて、分析ルートと除外項目を設定します。
  2. Migration Audit を開きます。Run Blueprint Audit をクリックするか、ヘッダーの Scan + audit を使います。
  3. 検査済み数と検出された Blueprint 数、検査の失敗を確認します。まず Blockers を確認し、次に Warnings と Info を確認します。
  4. 検出事項を選び、根拠、安定したルール ID、Blueprint の構造、推奨される次の対応を読みます。Open Blueprint または Show in Content Browser で確認します。
  5. 結果をエクスポートし、プロジェクトに適した変更を行います。手動でコンパイルとテストを実施してから、監査を再実行します。

まず検査のカバレッジを確認する

  • No Blueprint audit: 前回の通常スキャンには、任意の監査が含まれていません。
  • No Blueprints in scope: 想定外の場合は、設定したルートと除外項目を確認してください。
  • Inspection failures: 一部のアセットを読み取れなかったため、レポートのカバレッジは部分的です。
  • Completed: 予定された検査と分析が完了しました。移行先エンジンとの互換性を証明するものではありません。

Blueprint 検査は明示的に選択して実行し、範囲内のアセットをメモリに読み込みます。現在の読み込み済みコンパイル状態を参照し、コンパイル、親クラスの変更、再構築、削除、明示的な保存は実行しません。エンジンの読み込みによってメモリ上の状態が変わる場合がありますが、監査はその状態をひそかに保存したり、既存の未保存フラグを解除したりしません。

プロジェクトのコピーで実際のエンジン移行をテストしてください。 このレポートは現在の構造上の問題と確認事項を見つけます。新しいエンジンの API 変更、シリアライズの変更、C++ の動作、動的に読み込む参照は、移行先バージョンで引き続きテストする必要があります。

しきい値は確認を促す目安であり、互換性の限界ではありません。設計に合わせてプロジェクト設定で既定値を変更してください。エクスポートには、実際に使った値が記録されます。

CSV と JSON のエクスポート

  1. スキャンを完了させます。移行監査の検出事項を含めたい場合は、先に任意の Blueprint 監査を実行します。
  2. ヘッダーの Export、または移行監査の Export CSV / Export JSON を使います。
  3. UI に表示されるエクスポート先のパスを確認します。移行監査のエクスポート操作では、そのパスもクリップボードへコピーされます。
  4. <Project>/Saved/DependencyTracer/、または Report Export Dir で設定したディレクトリにファイルがあります。

どちらの形式も、利用できる監査データを含むスキャンレポートをエクスポートします。監査のエクスポート対象は、現在の検索や重大度フィルタで表示されている行だけではありません。

  • CSV: スプレッドシートでレポートの各セクションを確認したり、レビュー用に共有したりできます。
  • JSON: 比較や独自ツールでの利用に向けて、構造化されたスナップショットを保持できます。

移行データには、カバレッジ、検出事項、Blueprint ごとの指標、実際に使用したしきい値が含まれます。CSV には複数のレポートセクションがあり、JSON はスキーマバージョン 1.0 を使用します。どちらも完全な依存関係グラフは含みません。同じ範囲と設定のレポートを比較してください。範囲の変更が、合計や検出事項の変化の理由となる場合があります。

その後に通常スキャンを行うと、監査結果は監査を無効にしたスキャン結果で置き換わります。キャンセルや失敗の場合は、前回完了したレポートを保持します。エディタを開き直したら、新たにスキャンしてください。

トラブルシューティング

Tools に Dependency Tracer が表示されない

Edit > Plugins でプラグインを有効にして再起動します。ディスクリプタが正しいプラグインフォルダの直下にあり、パッケージがエンジンのバージョンに合っているか確認してください。ソースからの手動インストールには、エンジンに対応する C++ ツールチェーンと、エディタターゲットのビルド成功が必要です。

スキャンが空、またはフォルダが含まれない

Analysis Roots と Excluded Folders を確認します。/Game/Characters などのパッケージパスを使ってください。調べたい範囲に必要ならプラグインコンテンツを有効にし、新たにスキャンします。

サイズが不明、または予想より小さい

アセットを保存して再スキャンします。結果には、アセットレジストリで確認できるディスク上のパッケージサイズを使用します。未保存またはサイズ不明のものは除外される場合があり、走査が不完全なら下限値となる場合があります。クック後の出力は、保存済みパッケージのサイズと異なることがあります。

未使用候補が実際にはゲームで読み込まれる

動的なパスと外部の読み込みシステムを確認します。関連フォルダを Additional Root Folders に追加し、再スキャンしてください。参照分析では、実行時の文字列による読み込みをすべて推測することはできません。

依存関係マップが古い結果を表示する

新しいスキャンの完了を待ち、Reload map をクリックします。選択したルートとハード/ソフト参照のフィルタを確認してください。表示上限でリンクが省略される場合があります。別のノードにフォーカスして続きを調べます。

移行監査で監査未実行と表示される

通常の Scan project は Blueprint のグラフを検査しません。Migration Audit を開き、Run Blueprint Audit または Scan + audit を使ってください。

Blueprint の検査が失敗した

アセットを手動で開き、欠けている親クラス、提供元、パッケージの問題を確認します。解決してから監査を再実行してください。それまでは、カバレッジは部分的です。

検出事項が表示されない

検索を解除し、すべての重大度フィルタを有効にします。検査済み数と検出数、範囲を確認してください。検出事項なしで監査が完了しても、現在のルールで何も見つからなかったという意味であり、将来のエンジン移行を保証するものではありません。

レポートをエクスポートできない

分析の完了を待ちます。出力ディレクトリと書き込み権限を確認し、Window > Developer Tools > Output Log で Dependency Tracer のメッセージを読んでください。

Unreal がモジュールの不足や非互換を報告する

エンジンのマイナーバージョンに正確に合うアーカイブを選び、プラグインの重複インストールを確認します。ソースパッケージは、互換性のある C++ ツールチェーンでビルドする必要があります。別のエンジンバージョンの DLL をインストール先に混在させないでください。

よくある質問

プラグインはアセットを削除・書き換えますか？

未使用アセットのページは候補とエディタ内の移動操作を提供します。Blueprint 検査はアセットを読み込みますが、明示的にコンパイルや保存を行いません。変更と整理は、利用者が別途確認して実施する作業です。

表示された回収可能サイズ分の容量が必ず空きますか？

表示値は、確認すべき候補の既知のパッケージサイズです。削除する前に用途を確認してください。依存関係、クック、圧縮によって、配布ビルドに実際に含まれる内容は変わります。

大きいルートのサイズを合計できますか？

複数のルートは同じ依存先を共有することがあります。依存先を含むサイズを合計すると、共有パッケージを重複して数えます。別の観点から確認するには、種類別の合計や実測したビルドを使ってください。

検出事項がなければ移行の成功が保証されますか？

いいえ。レポートは現在の Blueprint 構造と読み込み済み状態を確認します。実際の移行先エンジンでプロジェクトのコピーを検証し、C++ コード、提供元、コンテンツ、動作をテストしてください。

移行準備レポートは含まれていますか？

はい。Dependency Tracer 1.1.0 には、従来の依存関係・サイズツールとともに含まれています。

パッケージ化したゲームに Dependency Tracer は必要ですか？

プラグインのモジュールはエディタ専用です。調査用の UI は、パッケージ化したゲーム内では動作しません。

分析にオンラインサービスは必要ですか？

プロジェクト分析は Unreal Editor 内でローカルに実行します。CSV と JSON のレポートは、選択したローカルディレクトリに書き込みます。

サンプルプロジェクトやスクリーンショットは自分のスキャンの一部ですか？

スクリーンショットは、専用に作成したデモプロジェクトを示しています。実際のスキャンは、設定したプロジェクトのアセットを使用します。ガイドのサンプルサイズや検出事項は、プラグインに組み込んだ固定の結果ではありません。

バージョンとサポート

このガイドは、Dependency Tracer 1.1.0 と、Windows 64 ビットの Unreal Engine 5.5、5.6、5.7、5.8 を対象としています。

1.1.0 に含まれる機能

依存関係カードとインスペクタを備えた Project Atlas UI、ハード/ソフト参照の経路、未使用コンテンツの調査、ルート別・種類別のサイズレポート、CSV/JSON エクスポート、Blueprint の移行準備レポートが含まれます。

エンジンの互換性は、Win64 上の UE 5.5.4、5.6.1、5.7.4、5.8.0 で確認しました。このリリースの検証環境では、Mac と Linux での実行は確認していません。
